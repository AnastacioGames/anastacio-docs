Экспорт в Android собирает **APK**: приложение, которое запускает внутри себя [Web](../web/)-версию игры офлайн, без интернета. Поэтому сначала настройте и проверьте Web: его сенсорное управление и предупреждения действуют и здесь.

## 1. Что установить заранее

Движок **не** включает инструменты Android. Установите их один раз:

1. **[Android Studio](https://developer.android.com/studio)**. Он содержит **JDK** (Java) и **Android SDK** — две вещи, нужные движку.
2. Откройте Android Studio один раз и дождитесь окончания загрузки SDK.
3. В **Tools > SDK Manager > SDK Platforms** установите **Android SDK Platform 37**.

Движок сам находит Android Studio (он также проверяет `JAVA_HOME` и `ANDROID_HOME`). Если он установлен в другом месте, укажите папки в **Tools > JDK** и **Android SDK** в панели.

## 2. Откройте панель

**Properties > Export Game > Android (Web)**.

![Панель Android](../../../../assets/exportar/android_en.png)

## 3. Приложение

| Поле | Что делает |
|---|---|
| **App ID** | Уникальный идентификатор приложения, например `com.yourname.yourgame` (буквы, цифры и `_`, разделённые точками; каждая часть начинается с буквы). |
| **App name** | Название под значком. Если пусто — используется имя файла. |
| **App version** | Версия, которую видит игрок, например `1.0`. |
| **Version code** | Целое число. **Увеличивайте его с каждой новой версией** (1, 2, 3...), иначе телефон откажется обновлять. |
| **App icon** | Квадратный PNG, лучше 512×512. Если пусто — стандартный значок Android. |
| **Screen orientation** | **Automatic** (поворачивается вместе с телефоном), **Landscape** или **Portrait**. |

:::caution
**Никогда не меняйте App ID после публикации.** Android посчитает это другим приложением: у игроков будет два значка, и они потеряют сохранения.
:::

## 4. Сборка

- **Build type**:
  - **Debug (testing)**: для проверки на **вашем** телефоне. Ключ не нужен. Используйте во время разработки.
  - **Release (players)**: финальная версия, подписанная вашим ключом. Используйте для выпуска.
- **Destination**: папка для APK, отчёта и лога (по умолчанию `//android/`).
- **Touch controls**: то же экранное управление, что и в панели Web.

## 5. Ключ подписи (.jks)

Нужен только для **Release**. Каждое приложение Android должно быть подписано, и **каждое обновление должно подписываться тем же ключом**, что и первый выпуск.

**Этот файл не нужно где-то брать: движок создаст его за вас.**

1. Установите **Build type** в **Release (players)**. Появится блок **Release Signing**.
2. Заполните:
   - **Key alias**: имя ключа внутри файла. Можно оставить `upload`.
   - **Key password**: пароль **не короче 6 символов**.
3. Нажмите **Create key**.

Движок использует `keytool` из JDK для генерации ключа (RSA 4096, действует около 27 лет) и заполняет поле **Signing key**. Если вы оставили это поле пустым, файл сохраняется в:

```
C:\Users\<you>\RangeAndroidKeys\<App ID>.jks
```

Чтобы выбрать другое место, укажите путь к файлу в **Signing key** **до** нажатия **Create key**. Движок никогда не перезаписывает существующий ключ.

:::danger[Сделайте резервную копию ключа и пароля]
Скопируйте `.jks` на флешку или в облако и запишите пароль в надёжном месте. **Если вы потеряете что-то одно, вы больше не сможете обновлять игру**: придётся публиковать её как новое приложение, и игроки потеряют сохранения. Не храните ключ внутри проекта или в Git.
:::

Уже есть `.jks` от другой игры или из Android Studio? Его можно использовать: укажите его в **Signing key** и заполните его alias и пароль.

Пароль не сохраняется в `.range`. После повторного открытия движка введите его снова перед сборкой.

## 6. Соберите APK

Нажмите **Build APK**. Движок сохраняет файл и запускает Gradle в фоне (первый раз дольше, потому что скачиваются зависимости). Прогресс отображается в панели.

Результат попадает в **Destination**: `.apk`, `android-report.json` и `gradle.log` (откройте его, если что-то пошло не так).

**Also build AAB (Google Play)**: дополнительно собирает `.aab` — формат, **которого требует Google Play**. APK всё равно собирается, чтобы его можно было установить на телефон.

## 7. Установка на телефон

1. На телефоне включите **Параметры разработчика** (в *О телефоне* нажмите 7 раз на *Номер сборки*), а в них — **Отладку по USB**.
2. Подключите телефон к ПК USB-кабелем и примите на телефоне запрос *«Разрешить отладку по USB?»*.
3. Нажмите **Install on phone**. Игра установится и откроется сама.

Можно также скопировать `.apk` на телефон и открыть его из файлового менеджера (Android попросит разрешить «неизвестные источники»).

## 8. Публикация в Google Play

1. Соберите в **Release** с включённым **Also build AAB**.
2. В [Google Play Console](https://play.google.com/console) создайте приложение и загрузите `.aab`.
3. В первый раз согласитесь на **Play App Signing**: Google хранит финальный ключ, а ваш `.jks` становится *ключом загрузки*. Резервную копию всё равно храните.
4. Для каждого обновления: увеличьте **Version code**, соберите снова **тем же ключом** и загрузите новый `.aab`.

## Частые проблемы

| Сообщение | Решение |
|---|---|
| *JDK and Android SDK not found* (или *JDK not found*) | Установите Android Studio или укажите папки в **Tools**. |
| *The Android SDK ... does not have platform 37* | Android Studio > SDK Manager > установите **Android SDK Platform 37**. |
| *No phone connected* | USB-кабель подключён, **отладка по USB** включена. Попробуйте другой кабель: некоторые только заряжают. |
| *The phone did not authorize this computer* | Разблокируйте телефон и примите запрос отладки по USB. |
| *The phone already has ... signed with another key* | На телефоне есть версия, подписанная другим ключом (например, Debug). Удалите её и установите заново. |
| *The phone has a newer version* | Увеличьте **Version code**. |
| Ошибка пароля или alias при сборке | Пароль или alias не соответствуют `.jks`. |
